What is minos?

Minimalism, stability, coherence, control, beauty.

A Linux based OS with focus in simplicity, elegancy and stability, primarily targeted at advanced users and developers, delivered as a thin layer of packages on top of Ubuntu LTS. Install Ubuntu, add one archive, install one package. Rolling updates over each LTS; minos has no named releases of its own.

minos-core
no X, for servers and terminals
minos-desktop
minos-core plus an i3 tiling desktop

Runs on Ubuntu LTS 22.04 · 24.04 · 26.04.

How do I install it?

How do I install it?

flavour i3 desktop, includes minos-core

On Ubuntu LTS, add one archive and install one package:

$ sudo add-apt-repository ppa:minos-archive/main$ sudo apt-get update$ sudo apt-get install minos-core # servers, terminals$ sudo apt-get install minos-desktop # i3 desktop, includes minos-core

The same in one line, desktop or core:

$ sh <(wget -qO- minos.io/s) desktop

Onto a blank disk, from any live USB:

$ wget -qO s minos.io/s && sudo sh s live desktop /dev/sdX username passwd

On Ubuntu LTS 22.04 · 24.04 · 26.04.

What is in minos-core?

No X. For servers and terminals.

shell
bash in vi mode, with shundle plugins: aliazator, autocd, colorize, eternalize; wcd to jump between directories
tmux + mosh
prefix Ctrl-a, tundle plugins, tmux launched on every ssh login
vim
vundle and about 50 plugins, each loaded when it is needed
cmdfound
from command not found to executed in seconds: it asks channels (github releases, aqua, nix, docker…) who can provide the missing command, picks the quickest and runs it
commands
the author's small ones, kept current through shundle: trash, an rm that keeps what it deletes; compress / extract; uimg
apt
recommends and suggests off
sudo
insults on, where sudo is the classic one; sudo-rs, the default from 26.04, has none

Where else does it run?

Vagrant

Boxes for VirtualBox: minos-core on 22.04, 24.04 and 26.04, minos-desktop on 24.04.

$ vagrant box add https://minos.io/vagrant/core-24.04.json$ vagrant init minos/core-24.04 && vagrant up

VirtualBox

The same machine without Vagrant, as an appliance:

$ VBoxManage import minos-core-24.04.ova

Packer

Both come from one Packer recipe: Ubuntu's live-server ISO, installed by Ubuntu's own installer with the install recipe of minos. Build your own from minos-org/packers:

$ packer build -var release=24.04 -var flavour=core -var ssh_key=PATH/vagrant.key.ed25519 .

AWS and other clouds

Start an Ubuntu LTS server and add minos to it:

$ sh <(wget -qO- minos.io/s) core

Docker

minos-core goes into a plain Ubuntu container:

$ docker run -it ubuntu:24.04 bash# apt-get update && apt-get install -y wget# sh <(wget -qO- minos.io/s) core

Why is it built this way?

Six principles decide what goes in.

  1. Minimalism

    use as few elements as possible but not less

    A dependency is added when something breaks without it, never because it is nice to have; apt runs without recommends or suggests.

  2. Coherence

    modularity and composition over generalization

    Small tools that call each other, and one config file instead of one per tool.

  3. Stability

    incremental over revolutionary

    minos rides Ubuntu LTS and rolls on top of it, with no named releases of its own. A change that works on the newest LTS must not break the older ones still supported.

  4. Control

    everything is configurable; toggles over multiple choice

    Every module of a settings package can be turned off with dpkg-reconfigure minos-core-settings, and a ~/.minos/not_override file keeps your home untouched.

  5. Pluggable

    components are plugin based

    The shell, tmux and vim each have a plugin manager: shundle, tundle and vundle.

  6. Beauty

    subjective; mostly black for now

Keyboard over pointing, vi-like everywhere, working out of the box.

How is it configured?

One file for everything: /etc/minos/config, and ~/.minos/config for yours, in plain key value lines.

wallpaper /usr/share/minos/wallpapers/sunlight.pnglauncher dmenu-launcherterminal x-terminal-emulatorfile-manager pcmanfmpdf zathuranetwork-manager cmst -dbattery-alerts 20,15,10

Read a value with minos-config:

$ minos-config wallpaper/usr/share/minos/wallpapers/sunlight.png

Every key: minos.io/doc/config

How is it developed?

A rolling release over LTS: frequent, small updates to each supported Ubuntu LTS, and no named releases of its own.

One package, two repositories

Every package is the program (foo) and its packaging (foo-deb, only debian/), each in its own git repository under github.com/minos-org. A package is accepted when the same packaging builds on every supported LTS: with few hands, one packaging per release is not an option.

Recipes

Launchpad mixes the two with a source recipe and builds the packages into the archive, ppa:minos-archive/main:

# git-build-recipe format 0.4 deb-version 1:{time}+git{revno}-minoslp:~minos-archive/minos/+git/foonest-part deb lp:~minos-archive/minos/+git/foo-deb debian debian

Checks

Before a change ships, it is built and installed in clean containers of every supported release.

Defaults

Programs are chosen for good documentation, flexibility, configurability and few dependencies: composition over generalization, keyboard over pointing, graphical ones only when they are light. Behaviour: toggles over multiple choice, vi-like, working out of the box.

The whole story: minos, a tiling wm linux distribution.

Where does it come from?

minos is old: a personal Ubuntu respin, worked on in spare time since about 2010.

  1. 2014 its first packages: boot and login themes, artwork, the desktop tools
  2. 2015 minos.io, and the installer minos.io/s
  3. 2017 the two metapackages, minos-core and minos-desktop; the first Vagrant boxes
  4. 2018 installs onto a blank disk from any live USB; runs on Ubuntu 14.04, 16.04 and 18.04
  5. 2022 20.04 in, 14.04 out
  6. 2026 22.04, 24.04 and 26.04; cmdfound in place of static-get
